# مراقبة سعة قاعدة البيانات

الميزانية الافتراضية **500,000,000 بايت**، محفوظة في الإعداد الخاص `capacity_budget_bytes`. هذه ميزانية تشغيل يحددها صاحب التطبيق، وليست قراءة لحصة Supabase الفعلية أو حالة الاشتراك. يقيس المراقب `pg_database_size(current_database())`، أي حجم قاعدة PostgreSQL بما فيها الجداول والفهارس. لا يقيس ملفات Storage أو نقل البيانات أو حدود خدمات اللعبة.

بعد تطبيق الترحيل `202609160010_capacity_monitor.sql` وإعداد الجدولة الأصلية بملف `supabase/operations/enable_adaptive_scheduler.sql`، ينفّذ مالك قاعدة البيانات ملف `supabase/operations/enable_health_monitor.sql`. ينشئ مهمة `brawl-capacity-health` مرة كل ساعة، عند الدقيقة11، إذا لم تكن موجودة. إعادة تطبيقه تحافظ على مهام الجدولة الموجودة ومواعيدها. يمكن للمالك أخذ قراءة مباشرة عبر:

```sql
SELECT public.sample_database_capacity();
```

يستمر القياس عند إيقاف المزامنة مؤقتًا. لا يرسل المراقب طلبات إلى مصادر اللعبة، ولا يغيّر وتيرة المزامنة أو الاشتراك، ولا يحذف بيانات النادي. ينظّف فقط قياساته الجديدة الأقدم من90 يومًا: يحتفظ `capacity_samples` بصف يومي يحتوي آخر قراءة وأعلى حجم رُصد في ذلك اليوم.

يبدأ التحذير عند70%، والمستوى الحرج عند90% من الميزانية المحددة. يصدر تنبيه التحذير الأول، ثم تنبيه فوري عند التصاعد إلى المستوى الحرج. إذا استمر التجاوز يتكرر التنبيه بعد24 ساعة؛ يبقى هذا القيد عبر تغيير اليوم والانخفاض المؤقت لتجنب تكرار التنبيهات قرب الحدود. لا تُرسل رسالة تعافٍ منفصلة. يتبع إنشاء التنبيهات وتسليم Discord إعداد `notifications_enabled`، بينما يستمر تسجيل القياسات عند تعطيل الإشعارات.

يحدّث ملف التشغيل دالة الجدولة بحيث ينطبق `sync_scheduler_enabled` على المزامنة وحدها. عند إيقافها مؤقتًا، يستمر تسليم الإشعارات المستحقة إذا كان `notifications_enabled=true`؛ وعند تعطيل الإشعارات لا يُرسل طلب تسليم. تُضاف سجلات مهمة السعة إلى التنظيف الموجود بعد7 أيام، دون إنشاء مهمة تنظيف أخرى أو تعديل سجلات المهام غير التابعة للتطبيق. إذا أُعيد تطبيق ملف الجدولة الأصلي لاحقًا، أعد تطبيق ملف مراقبة السعة بعده لأنه يحدّث الدالتين المشتركتين.

أرقام الحجم والميزانية والنسبة خاصة بالإدارة وبحمولة Discord الخاصة. الإشعار العام رسالة عربية عامة بلا أرقام سعة. لا تستطيع الأدوار `anon` و`authenticated` قراءة الجدول أو تشغيل القياس، ويستطيع `service_role` قراءة القياسات فقط؛ تنفيذ الدالة خاص بمالك قاعدة البيانات.

تعيد قراءة الإدارة الحالة `unknown` عند غياب القياس أو فساد بياناته أو وقوع وقته في المستقبل أو تعذر قراءة الجدول. إذا تجاوز عمر القراءة ساعتين تُعلَّم `stale` مع الاحتفاظ بآخر قيمة موثقة؛ لا تُعرض على أنها قياس حالي. تعكس النسبة مقارنةً بالميزانية المحفوظة وقت القياس، وقد تتجاوز100%.

الترحيل لا يحتاج `pg_cron` أثناء اختبار الاستعادة المحلي. إعادة تفعيل المهمة في مشروع بديل تتم بملف التشغيل المنفصل بعد استعادة التطبيق والتحقق منه.

للتحقق دون تشغيل مزامنة أو إرسال Discord يدويًا:

```sql
SELECT jobname, schedule, active
FROM cron.job
WHERE jobname IN ('brawl-adaptive-sync','brawl-notifications',
  'brawl-scheduler-log-retention','brawl-capacity-health')
ORDER BY jobname;

SELECT sampled_at, level, clock_timestamp()-sampled_at AS sample_age
FROM public.capacity_samples ORDER BY sampled_at DESC LIMIT 1;
```

تظهر أربع مهام بأسماء فريدة. تبقى المزامنة كل دقيقتين، والتسليم في الدقائق المتناوبة، والتنظيف اليومي عند03:13 UTC كما كانت قبل التحديث؛ وتُضاف قراءة السعة الساعية. تحقّق من ظهور قراءة جديدة بعد الموعد التالي ومن أن الإشعارات تُسلّم في الجدولة المعتادة عندما تكون مستحقة ومفعّلة.
